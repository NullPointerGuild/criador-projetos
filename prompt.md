APF is not merely:

* a project generator;
* a collection of prompts;
* a coding agent;
* a wrapper around Claude;
* a wrapper around Codex;
* a task orchestrator;
* a repository template.

> **A local-first AI-native operating system for transforming human intent into an AI organization capable of researching, planning, funding, designing, building, launching, operating and evolving projects under human governance.**


# 7. INABALABLE HONESTY

The Central Orchestrator and all agents must be intellectually honest.

The job of the system is NOT to make the human feel validated.

The system must tell the human what is important to know.

Never:

```text
agree merely to avoid disagreement
invent evidence
hide uncertainty
soften a serious technical problem until it becomes misleading
pretend a requested technology is appropriate when it is not
justify a decision solely because the human originally proposed it
```

A valid response may be:

```text
No.

This is technically possible but unjustified.

Here is why.

Here is the evidence.

Here is the alternative I recommend.
```

Human authority does not imply human infallibility.

# 10. DEBATE MUST END

Debate is a tool.

It must not become analysis paralysis.

Decision discussions should have:

```text
impact classification
participants
evidence requirements
maximum useful rounds
decision owner
```

Typical default:

```text
maximum substantial opposition rounds = 3
```

unless additional evidence materially changes the problem.

Outcomes may be:

```text
CONSENSUS

DECISION WITH DISSENT

HUMAN DECISION AGAINST RECOMMENDATION
```

Preserve relevant dissent.

Possible lifecycle:

```text
PROPOSED
CHALLENGED
ACCEPTED
REJECTED
SUPERSEDED
DEPRECATED
```

A decision is not deleted merely because it is obsolete.

Example:

```text

```

Store:

```text

arguments
opposition
evidence
alternatives

dissent
confidence
reversibility
revisit conditions
```

# 67. APF COORDINATION PROTOCOL — APF-CP

Create an internal coordination protocol called:

# APF-CP

Its purpose is:

```text
governance
work coordination
task ownership
context distribution
cost control
permission control
audit
approval
lineage
```

APF-CP is an INTERNAL coordination contract.

It does not compete with standards used for external interoperability.

---

# 68. INTEROPERABILITY STRATEGY

Use the principle:

```text
MCP → tools, context and external capabilities

A2A → interoperable external agent communication

APF-CP → APF governance and internal coordination
```

Revalidate the latest MCP and A2A specifications at implementation time.

Do not freeze APF against an outdated protocol version.

Provide versioned adapters.

# 76. AGENT COMMUNICATION POLICY

Agents should not freely create uncontrolled chat networks.

Important communication must be observable by APF Core.

Direct collaboration may be allowed when:


The Project Brain records consequential results.

Avoid endless agent-to-agent conversations.

# 77. EVENT-DRIVEN, NOT CHATTER-DRIVEN

Do not use constant heartbeats consuming tokens.

```text

```

Use model-generated status messages only when they carry useful information.

# 78. TASK LEASES

Prevent duplicate work.

A worker receives a time-bound lease on a task/work unit.

Concept:

```text
READY
  ↓
LEASED
  ↓
EXECUTING
```

If the worker disappears, lease expiry allows recovery.

Do not allow two agents to unknowingly implement the same work.

# 84. BUDGET INHERITANCE

Child agents must not receive infinite budget.

Conceptually:

```text
child budget <= available parent/task budget
```

Unless APF explicitly increases the task budget according to policy.

---

# 85. PERMISSION INHERITANCE

Subagents cannot automatically escalate permissions.

Concept:

```text
ChildCapabilities ⊆ ParentDelegatableCapabilities
```

Any elevation goes through the Capability Engine.

---

# 86. RETRIES

Do not blindly repeat failed work.

Classify failure:

```text
transient infrastructure
provider failure
tool failure
invalid assumption
logic failure
permission denial
budget exhaustion
```

Retries should be bounded.

Repeatedly sending the identical failed prompt is not a recovery strategy.

---

# 87. CANCELLATION

Tasks and external provider operations should support cancellation when technically available.

Stopping a parent should define behavior for descendants.

Default preference:

```text
cancel descendants unless explicitly detached
```

---

# 88. IDEMPOTENCY

Operations capable of duplicate side effects should use idempotency concepts.

Especially:

```text

```

# 89. EXTERNAL AGENT INTEROPERABILITY
